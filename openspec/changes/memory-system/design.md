## Context

项目已有好感度系统（5 阶段）和情绪系统（6 状态），但对话历史仅存在内存中。需要持久化存储 + 语义检索让诺艾尔跨对话记住用户。PostgreSQL + pgvector 已就绪。

## Goals / Non-Goals

**Goals:**
- 对话历史持久化，服务重启后完整恢复
- 用户画像自动提取（结构化事实）
- 对话摘要自动生成（每 10 轮一段）
- 向量语义检索（pgvector）
- 记忆 → Prompt 注入（Layer 4 + 5）
- 异步执行，不阻塞用户回复

**Non-Goals:**
- 不做多用户隔离（单用户项目）
- 不做主动遗忘机制（MVP 只追加）
- 不做分层摘要（每段独立，不累积）
- 不做实时画像提取（攒 10 轮批量处理）

## Decisions

### Decision 1: 触发机制 — 异步批量而非每轮

**Why**: 每轮都调 LLM 提取画像成本高（~900 次/月），且阻塞用户回复。改为每 10 轮异步触发，成本降低 97%（~30 次/月），用户零感知。

**方案**:
- 正常对话：只写 DB，不调额外 LLM
- 每 10 轮结束：后台异步任务读 DB → 提取画像 + 生成摘要

### Decision 2: 表结构 — 3 张表

| 表 | 用途 | 查询方式 |
|----|------|---------|
| `user_profile` | 用户画像（JSONB facts） | 全量注入 + 语义检索 |
| `chat_history` | 对话历史 + 状态快照 | 时间范围（最近 N 轮） |
| `conversation_summary` | 对话摘要段 | 语义检索 + 时间序 |

**Why 3 张而非 1 张**: 查询模式不同。画像全量注入、历史按时间、摘要按语义。混合存储会导致索引混乱。

### Decision 3: chat_history 增加调试字段

新增 `raw_content`（AI 原始输出）、`emotion`、`affection_level`、`affection_points`（状态快照）。

**Why**: 排查问题时能还原"当时什么状态、说了啥、过滤后变了啥"。user 消息这些字段为 NULL。

### Decision 4: 摘要不累积

每段摘要只覆盖触发的那 10 轮，独立存储。

**Why**: 累积摘要会越来越长、越来越模糊。早期细节已存入画像，不需要留在摘要里。每段摘要是"那个时期"的精确快照。

### Decision 5: Embedding 模型 — bge-small-zh-v1.5

512 维，中文专用，95MB。替代原方案的 paraphrase-multilingual-MiniLM-L12-v2（470MB，多语言通用）。

**Why**: 中文语义理解更好、体积小 5 倍、512 维兼容现有配置。

### Decision 6: 异步任务读 DB 而非内存

**Why**: 内存滑动窗口满了会裁剪，异步任务可能读不到完整 10 轮。DB 存完整历史，两者职责分离。

### Decision 7: 画像存储 — JSONB 而非列式

```json
[
  {"key": "name", "value": "小明", "updated_at": "2026-08-16T10:30:00", "embedding": [...]},
  {"key": "pet", "value": "养了一只猫", "updated_at": "2026-08-14T15:20:00", "embedding": [...]}
]
```

**Why**: 用户信息动态未知，JSONB 灵活，加字段不用改表。每条事实独立 embedding，支持语义检索。

## Prompt 注入策略

**Layer 4（用户画像）:**
```
你了解到的关于用户的信息：
- 名字：小明
- 职业：后端开发
- 喜欢：猫、原神、喝咖啡
- 不喜欢：下雨天
```

**Layer 5（对话记忆）:**
```
【最近摘要】
上次聊天（3天前）：用户提到工作压力大...

【相关记忆】
- 用户之前说过想养第二只猫
- 用户提过在原神里抽到了诺艾尔
```

## Token Budget

```
Layer 1:  ~800  人设
Layer 2:  ~150  好感度
Layer 3:   ~80  情绪
Layer 4:  ~200  画像（最多10条事实）
Layer 5:  ~300  记忆（2段摘要 + 检索3条）
─────────────────────────
system prompt: ~1530 tokens
history:       ~1500 tokens（10轮）
current:       ~50 tokens
─────────────────────────
总计:          ~3080 tokens
```

## Risks / Trade-offs

### Risk: Prompt 过长
- **Mitigation**: 画像最多 10 条、摘要最多 2 段、检索最多 3 条，设置 token 上限

### Risk: 异步任务失败
- **Mitigation**: 任务失败不阻塞对话，下次触发时补执行

### Risk: LLM 画像提取不准确
- **Mitigation**: 画像只作为辅助信息，关键信息以用户原文为准

### Risk: embedding 模型首次加载慢
- **Mitigation**: 启动时预加载模型到内存，后续调用无延迟

## Migration Plan

1. 新增表和代码，不修改现有 affection/emotion 表
2. 首次启动时 `create_tables()` 自动建表
3. 旧对话历史在内存中，重启后丢失（可接受，MVP 阶段）
4. 新对话自动写入 DB，逐步积累记忆
